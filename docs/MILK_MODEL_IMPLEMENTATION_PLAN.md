### 3.2 日運転

Fan、WaterSystem、RoofSettingsへ `dailyStartHour` を追加。初期値はすべて8（08:00）。
時間はローカル代表日の時刻で、日付・タイムゾーン・夏時間の暦計算は導入しない。
入力は開始0以上24未満、0.25時間刻み。hoursPerDayは既存0〜24の有限値を維持する。

日計算の時刻t秒について：

```text
elapsed = positiveModulo(t - dailyStartHour*3600, 86400)
windowOn = enabled && hoursPerDay > 0 && elapsed < hoursPerDay*3600
fanOn = windowOn
waterOn = windowOn && onSec > 0 && elapsed % (onSec + offSec) < onSec
```

- 08:00から16 hのファンは08:00〜24:00。水系統8 hは08:00〜16:00。
- 22:00から4 hなら22:00〜翌02:00。午前0時には周期・残水をリセットしない。
- 各日の運転開始時刻に散水周期をONから開始する。24 h運転でもその開始時刻で周期を再開始するという仮定を記録する。
- 0 hは停止、24 hは常時運転枠、ON=0は供給なし、OFF=0は運転枠中ずっと供給。
- 運転枠終了時は供給・ファン寄与を止め、保持水はその後も蒸発する。
- 全ノズルは所属系統の枠と周期を使い、個別enabledを併用する。

本ポリシーを `daily-window-reset-v1` として保存する。日境界での無条件リセットと、開始時刻での意図した周期開始を区別する。
日水量・電力量も評価24時間の同じ運転判定から積算し、熱と資源量の時刻条件を一致させる。
循環ファンによる換気量の自動増加は追加しない。

既存60分試行は従来どおり「機器がONから始まる経過時間」として維持し、dailyStartHourは適用しない。
画面で日計算との違いを明記する。旧isOnを一括置換して60分計算や原表/受胎の挙動を変えない。

### 3.3 代表日と乳量係数

気象は `Project.environment` を24時間反復。初版は時刻別配列を保存・編集しない。
1秒刻みでt=0〜172799秒、最初の86400秒は準備のみ、次の86400秒を集計する。
屋根水・各地点の保持水はt=86400で引き継ぐ。日乳量計算は熱のreferenceプロファイルだけを使う。
betaの3条件は同じDから計算し、熱のlow/reference/highとの9通りの組合せは作らない。
準備区間の資源量は日使用量に含めない。

式は乳量仕様v0.1を使う。代表日モードではD[d-1]=D[d-2]=D[d]としてE=D。
Qref・beta・上限・重みを実装者判断で調整しない。

## 5. 計算・Worker・性能の構成

追加モジュールの目安（責務を保てば名称は変更可）：

| 追加先 | 責務 |
|---|---|
| `src/model/milk.ts` | 負荷・遅れ・上限・乳量・差・感度の純粋関数 |
| `src/model/dailySchedule.ts` | 日運転枠・周期・秒数積算 |
| `src/model/dailySimulation.ts` | 幾何の再利用、48時間の熱状態更新、日集計 |
| `tests/unit/milk.test.mjs` | MHの算術・境界・不正入力 |
| `tests/unit/dailySchedule.test.mjs` | 日跨ぎ・周期・0/24h・資源量 |
| `tests/integration/dailyMilk.test.mjs` | 全70地点・実設備・ハッシュ・保存・Worker契約 |

熱の式を別実装で複製せず、heatTerms、filmStep、solveRoof、捕水・風速幾何を再利用する。
必要な状態更新関数だけ抽出し、既存60分経路との数値一致を試験する。
windAtの時間条件は日運転状態と分離する。停止判定を旧hoursPerDayでもう一度適用しない。

WorkerのReplyを判別可能な `thermal-result / daily-result / error` とし、全メッセージにjobIdとinputHashを付ける。
同一ジョブ内で60分計算を先に返し、その後に日計算を返す。UIは前者だけでreadyにせず「乳量を計算中」とする。
日計算が失敗しても同一入力の60分結果は保持し、乳量を計算不可にする。
日結果は対応する60分結果へだけマージする。どちらもResultGateで古いjob/hashを拒否する。

現行の入力確定後100ms送信・計算中Worker終了を利用する。編集中は古い日乳量を最新値として表示しない。
Workerが同期ループ中にcancelメッセージを処理できると仮定しない。再編集時はterminateで中断する。
地点・視点・60分カーソルの変更だけでは再計算しない。

性能上の必須事項：

- 初版は日計算の1秒刻みと256レイを維持。黙って刻みを粗くしたり点を間引いたりしない。
- 固定配置のレイ・捕水率、セルへのミスト配分は時間ループ外で計算する。
- 同じ設備案はジョブ内で日集計を再利用。beta感度だけで熱を3回実行しない。
- 48時間×70点×全案のPointSample配列を保存しない。日計算は和・状態・収支だけを保持する。
- 屋根状態が時刻ごとに必要ならFloat64Array等の限定サイズを使い、全点へオブジェクト複製しない。
- 現行airCache/termsCacheは厳密な数値文字列がキーのため、濡れた屋根で時刻数に比例して増える。日計算へ無制限に持ち込まない。
- 既存60分結果だけが表示用seriesを持つ。JSONへ48時間の内部配列を出力しない。

測定は標準配置と40ファン・100ノズル/案で各3回。環境、60分結果までの時間、日結果までの時間、
再編集後に旧結果を拒否できること、メモリ取得方法と値を記録する。
初期目標は標準日計算10秒以内。これは未測定の操作性目標であり科学的要件ではない。
超過時は正確な再利用・キャッシュ・データ構造を改善し、測定結果を報告する。タイムアウト延長だけで達成済みとしない。

開始時刻が異なるファン、日跨ぎ時の周期、周期が24時間を割り切らない場合の開始時刻リセット。
資源積算と熱側運転マスクが一致することを独立した期待秒数で確認する。

### ブラウザの黄金経路

1. 標準起動。60分結果の後に日乳量が表示される。基準と初期Aは同じ値。
2. Aで屋根対策、ファン、ソーカー、ミストを変更。日負荷・日乳量・資源量を再計算。
3. 同じ配置で開始時刻・運転時間を変更。保存値・日運転・日資源量の一致を確認。
4. 日計算中に再編集。旧結果が最新結果に上書きされない。
5. 地点・視点・60分時刻を切替。牛群平均の日乳量は不変。
6. beta・Y0を変更し、上限・負の差・仮定の幅を管理された条件で確認。
7. コピー、Undo/Redo、保存、読込で結果が復元する。v8/不正JSONは現在案を保持して拒否。
8. 2Dフォールバックでも同じ主導線を通し、HTTP版と単体HTMLの版・結果を照合。

すべての設備操作で必ず乳量が増えることは要求しない。届かない配置、飽和、上限、温風などの条件を区別する。
