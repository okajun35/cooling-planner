## 1. 目的と完成イメージ

牛舎を大きく表示し、「見る → 設備を置く・動かす → 効果を見る → 案を比べる」が自然につながる画面にする。

現在の左右の常設パネルと縦に続くグラフ・表を、設備メニュー、選択対象のパネル、必要時に開く比較画面へ整理する。落ち着いた農場・建設シミュレーション風の見た目にする。

ユーザーの要望：

- 今のUIは機能が多く、入口と操作順が分かりにくい。
- 3D改修と同様に、ZIP内のゲーム用スキルを使う。
- 標準3D・リアル3D・2Dは維持する。
- 操作に沿った解説を付ける。
- PoCとしてシンプルに実装する。新しい大規模な基盤や独自の検証フレームワークは不要。
- 別Agentが実装するため、実装判断と完了条件をこの文書にまとめる。

成功条件：初めて開いた人が、説明書を先に読まなくても「編集案を選ぶ」「ファンを動かす」「基準との差を見る」まで進められる。ゲームの勝敗や唯一の正解は作らず、冷却効果・水・電力の違いを比較できるようにする。

## 4. 画面構成

```text
┌─────────────────────────────────────────────────────────┐
│ Cooling Planner   [基準] [編集A] [編集B]   気象  保存  … │
│ 選択地点の不足 …W / 60分平均    水 …L/日   電力 …kWh/日 │
├─────────────────────────────────────────────────────────┤
│ [風]                                    [標準/リアル/2D] │
│ [散水]                                                   │
│ [分布]               牛舎                 選択パネル     │
│ [屋根]                                    設備 or 地点  │
│                                                         │
│ 凡例（分布表示中）                 [全体][上面][側面]    │
├─────────────────────────────────────────────────────────┤
│ [ファン] [ソーカー] [ミスト] [屋根対策]                  │
│ 戻す / やり直す   ▶ サイクルを見る   [結果・比較] [?]   │
└─────────────────────────────────────────────────────────┘
```

### 常設するもの

- 案の選択：現在の案、基準として固定されている案を区別。
- 気象：現在の外気温・湿度を短く表示し、クリックで詳細を開く。「全案共通」を表示。
- 計算状態：入力中、配置編集中、熱計算中、日乳量計算中、完了、エラーを既存状態から表示。
- 上部要約：選択地点の放熱不足、水使用量、電力量の最大3項目。
- 画面端：表示切り替え、カメラ、設備メニュー、Undo／Redo、比較・ヘルプへの入口。

### 上部要約の定義

| 項目 | 値の取得元と表示 |
|---|---|
| 放熱不足 | 選択中の評価点の `meanDeficitW`。地点名と「60分平均」を併記 |
| 水 | 現在の案の `dailyMilk.resources.waterLPerDay`。案全体の「L/日」 |
| 電力 | 同じ `dailyMilk.resources.totalKwhPerDay`。「kWh/日」 |

日集計が未完了なら水・電力は「計算中」。異なる集計期間の旧値を代わりに使わない。取得できない値は理由に応じて「未評価」「比較不可」「計算エラー」とする。ゼロ埋めしない。熱結果だけ利用可能な段階は、熱結果を表示し、日集計を待つ。

### パネル

| パネル | 開き方 | 主な内容 |
|---|---|---|
| 設備 | 設備をクリック・設備一覧で選択 | 有効、向き、高さ、風速または流量、複製、削除 |
| 地点 | 牛床・採食帯などの面をクリック・地点一覧で選択 | 地点名、60分平均、基準差、放熱内訳への入口 |
| 屋根対策 | 下部メニュー | 遮熱・断熱・屋根散水、全体に適用する旨 |
| 気象 | 上部 | 外気温、湿度、日射。詳細に背景風速・空気交換等 |
| 結果・比較 | 下端 | 「案比較」「エリア」「時間変化」「参考影響」のタブ |
| ヘルプ | ? | 操作、結果の読み方、設備の作用、根拠・仮定 |
| 設定・保存 | 上部のメニュー | 保存、読込、寸法、単価、既存の共通設定 |

右側の選択パネルは同時に1つ。設備を選ぶと設備、評価点を選ぶと地点へ切り替える。閉じても対象の選択は残してよい。比較を開くと選択パネルを一時的に隠し、閉じれば元の選択へ戻す。

「参考影響」には既存の日乳量、仮定設定、受胎の参考シナリオ、掲載条件の参照への導線を残す。結果JSON、案のコピー、基準へ戻す、各系統のON/OFF、個別設備一覧も到達可能にする。

## 5. 見た目とサイズ

- 濃いグレーの不透明または十分に濃いパネル、読みやすい明るい文字。
- 選択は青緑、注意は橙など、少数の役割色に統一。ヒートマップの凡例色は既存仕様を維持。
- 日本語ラベルを優先し、英語の大きな見出しや番号付きセクションは外す。
- 数字には等幅数字を使い、値の桁が変わっても周囲を動かさない。
- アニメーションは選択や開閉に限定し、100〜200ms程度。動きを減らす設定にも従う。
- アイコンだけの主要操作を避ける。補助ボタンにもアクセシブルな名前を付ける。

| 画面 | 方針 |
|---|---|
| 1440×900、1366×768 | 基本画面の操作はページスクロール不要。牛舎の可視領域を画面幅の概ね65%以上確保。右パネルは約300〜340px |
| 1024×768 | ラベルを短くし、詳細パネルを収納。主要なボタンを押し出さない |
| 390×844 | 上部を圧縮し、詳細は下から開くパネルへ。高さは概ね画面の55%以内、内容だけスクロール。横スクロール禁止 |

初版の主対象はPCだが、小画面でも表示切り替え、設備選択、数値編集、比較、保存へ到達できること。タッチの配置は「タップで候補位置 → 配置ボタンで確定」とし、カメラ操作と取り違えない。ボタンの操作領域は約44pxを目安とする。

## 6. 設備操作

### 6.1 選択と編集

設備選択時は輪郭または既存の選択マーカーを強調し、設備名を表示する。右パネルの先頭は「有効」「向き」「高さ」「出口風速／ノズル流量」。座標、下向き角、運転開始、運転時間、噴霧半角、系統周期は詳細へまとめる。

ノズル個体の設定と系統全体の設定を見出しで区別する。現在の設備型が持たない項目は表示しない。向きは既存の90度回転ボタンと数値入力を利用できる。スライダーを追加する場合は1回の操作を1回のUndoにまとめる。

地点の結果は評価面を選ぶ。見た目の牛50頭と計算の評価点は一致しないため、「この牛の結果」とは表示しない。採食帯へ移した3頭を個体計算対象として扱わない。

### 6.2 新規配置

1. 編集案で「ファン／ソーカー／ミスト」を押す。
2. 配置モードに入り、設備の半透明プレビューと短い案内を表示。
3. ポインタに合わせて候補位置を更新する。
4. 有効な位置でクリックすると1台／1ノズルを確定。
5. 配置モードを終了し、追加した設備のパネルを開く。

初版は1個ずつ配置する。屋根対策はこの配置モードを使わない。選択した水系統がOFFなら「系統が停止中」を表示し、既存の系統ON操作へつなぐ。配置に伴う暗黙の系統設定変更はしない。

#### 座標とプレビュー

- Projectの床面座標は `x, y`、Three.jsの位置は `[x, heightM, y]`。対応を取り違えない。
- 3Dは設備の初期高さの水平面とポインタのレイを交差させる。画面に見えるプレビュー中心と確定位置が一致すること。
- 2DはSVGの座標変換を使って床面位置を取得する。
- 既存設備の初期値と既存の配置制約を共用する。
- 床外や既存の禁止条件に当たる位置は薄赤色と「ここには配置できません」で示し、確定しない。新しい物理衝突モデルは作らない。
- プレビューのメッシュ・マーカーをポインタ移動のたびに生成・破棄しない。単純な形状でよく、リアル設備を完全複製する必要はない。

#### 確定と取り消し

- プレビュー中はProject、保存、計算入力ハッシュ、Undo履歴、MCPの設備一覧を変更しない。
- 確定時に設備作成・座標設定・アンカー更新・選択を1回のStore編集で行う。
- `addFan()`の後に`updateDevice()`を呼ぶ2操作構成にしない。
- Esc、キャンセルボタン、別案への切り替え、表示モード切り替え、読込、画面のフォーカス喪失で未確定配置を取り消す。
- 既存設備ドラッグ中の `pointercancel` 等は既存のドラフトを取り消す。`lostpointercapture` の正常終了との区別も確認する。
- 配置モード中の左クリックは配置へ優先する。通常の面選択・設備移動と同時発火させない。
- 右ドラッグ等でカメラを動かせる場合も、その操作終了を配置確定と扱わない。

### 6.3 固定の基準案

基準案は閲覧可能、編集は不可。設備メニュー付近に「基準案は固定です」と「編集案Aで試す」を表示する。このボタンは案を切り替えるだけにし、既存の編集案を上書きしない。基準案のコピー／リセットは既存の明示操作を利用する。

## 7. 表示・結果・再生

- 風、散水は既存の `view.flow`、`view.particles` に接続。
- 分布表示は指標（放熱不足／放熱改善／風速／気温）と、リアル3DのヒートマップON/OFFをまとめて操作できるようにする。
- 標準3D・2Dでは既存の面表示を維持。リアル3Dのみにある機能は表示状態を明示する。
- 屋根断面と、牛等を隠す分析表示の違いを短く説明する。
- 全案共通目盛り、単位、無効値の表示を凡例に残す。
- 水滴・風の動きは作用の模式表現であることを、表示設定またはヘルプから確認できるようにする。

再生バーは「散水サイクル・0〜60分」。再生・停止、時間スライダー、倍率を維持。グラフは「時間変化」タブへ置き、放熱量・気温・保持水を切り替える。平均値カードと時刻値を混同しない。乳量・受胎がこの再生で時刻ごとに変化すると示さない。

結果更新は既存の `ResultGate` と入力ハッシュの一致を使う。古い結果を新しい設備の効果として表示しない。再計算完了の強調は一瞬の表示で十分。改善していない場合まで成功色や祝福表示を付けない。

## 8. ガイドと解説

初回ガイドは閉じられる小さな案内とし、3ステップにする。

1. 「暑さの分布を見る」：放熱不足の表示を案内。
2. 「ファンを選んで動かす」：固定案なら編集案へ切り替える導線を出す。
3. 「基準案と比べる」：比較パネルを開く。

ガイドが利用者の代わりに設備や気象を書き換えない。進捗は実際の操作で進める。スキップとヘルプからの再表示を用意する。既読フラグを端末に保存する場合はProjectとは別キーにし、localStorageが使えなくても操作を続けられるようにする。

設備メニューの一行説明例：

- ファン：牛の周囲の風を強める。
- ソーカー：牛体を濡らし、蒸発による放熱を促す。
- ミスト：蒸発で空気を冷やす。湿度も変わる。
- 屋根対策：屋根から受ける熱の条件を変える。

ヘルプには操作、設備の作用、指標の意味、集計時間、基準案との比較、モデルの仮定を用意する。「効果十分」を無条件な正解と説明しない。日乳量は仮説モデル、受胎は参考シナリオという既存の位置付けを明示する。

## 9. 実装構成

### データの経路

```text
UIまたはMCP → ProjectStore → 計算Worker → ResultGate → UI / Scene
                         ↘ Undo・保存

UIの開閉・配置候補 → ローカルUI状態 → DOM / プレビュー
```

UI用の状態は小さなTypeScriptモジュールで管理すればよい。新しい状態管理ライブラリは追加しない。

例：`src/ui/workspaceState.ts` に現在のパネル、比較タブ、選択対象の種類、配置候補、ガイド段階を保持する。設備IDや結果数値を別の真実として複製せず、必要時にProject／結果から取得する。新しいUI状態をProjectの保存スキーマに追加しない。

### 変更対象

| ファイル | 作業 |
|---|---|
| `src/ui/layout.ts` | 常設枠、選択パネル、比較パネル、ヘルプのDOM |
| `src/styles.css` | レイアウト、色、パネル開閉、小画面、フォーカス |
| `src/ui/panels.ts` | 大きな一括描画を分け、表示対象に応じて更新。必要なら数個のファイルへ分割 |
| `src/ui/timeline.ts` | 折りたたみ状態と再表示時のサイズ・現在時刻を扱う |
| `src/main.ts` | UI状態、選択通知、配置確定、パネル操作と既存Storeを接続 |
| `src/views/common.ts` | 配置候補の通知・プレビュー設定を必要最小限の共通APIとして追加 |
| `src/views/viewport3d.ts` | 3Dの配置位置取得、既存選択・ドラッグとの優先関係 |
| `src/views/svg2d.ts` | 2Dの配置候補・確定、同じ編集意図を通知 |
| `src/views/realistic3d.ts` / `threeBackend.ts` | 必要な場合だけ軽量なプレビュー描画。牛舎造形は維持 |
| `src/state/store.ts` | 任意座標への原子的な追加。既存の引数なし呼び出しを維持 |
| `tests/` | 新規操作と既存操作の回帰確認 |
| `README.md` | 新しい入口、配置手順、比較、ガイドの説明 |

### Store追加操作の推奨形

`addFan(pose?)`、`addNozzle(kind, pose?)` のように、省略可能な座標引数を追加する。既存MCPの引数なし呼び出しは従来位置で動作させる。新しいID生成、初期値、アンカー設定、検証、UndoはStore内に置く。確定位置を受け取ったUI側でProjectを直接書き換えない。

### DOM更新で壊しやすいところ

現コードの `renderControls()` は多数のIDに直接アクセスし、`renderResults()` は比較の描画も呼ぶ。パネルを削除・遅延生成するだけでは例外になる。初版は必要なパネルDOMを作って `hidden` 等で切り替える方式が簡単。描画関数を分ける場合は呼出元も合わせて直す。

設備設定を描き直すたびに入力フォーカス、カーソル、詳細の開閉を失わないようにする。再生中は既存の時刻専用更新経路を維持し、全設定パネルを毎フレーム再生成しない。パネル開閉だけでSceneを破棄・再生成しない。サイズ変更は既存のResizeObserverと連携させる。

### MCP・外部更新

MCPから設備選択、移動、削除、案変更、表示変更を行っても同じProjectStore購読から再描画する。設備IDが存在しなくなったパネルは閉じるか未選択表示へ戻す。

ローカルUIの設備／地点切り替えは選択イベントで決める。外部から選択IDが変わった場合も変更を検出する。両方同時に変わった場合は存在する設備を優先するなど、順序を固定する。外部からProjectが変更されたら未確定配置を取り消す。表示のみの更新では計算を走らせない。
