# Cooling Planner — 区画別の暑熱・冷却可視化仕様 v0.1

更新日：2026-09-28。仕様ID：`area-cooling-visualization-v0.1`。
状態：ユーザーが指定した4項目の設計・実装引継ぎ用。**本仕様の追加機能は未実装**。
アプリの実装・計算コード・配布物は今回変更しない。レビュー対応中の変更は保持する。

## 1. 目的と範囲

設備を移動したとき、どこの牛に作用が届き、どこに放熱不足が残るかを、2D・3Dの牛舎上で確認できるようにする。

今回定義する4項目：

1. 牛床ごと、採食・待機の区画ごとの面の色分け。
2. 「現在の放熱不足」と「基準案からの改善」の切替。
3. 区画選択による風速・濡れ方・放熱内訳の表示。
4. エリア別の平均と、局所設備の作用が届かない地点の表示。

既存の局所計算を使い、必要な集計・診断情報を追加する。CFD、空間内の熱移流、部分断熱、
牛の移動・滞在分布の変更、新しい乳量式は含めない。屋根条件・屋根裏温度・放射環境は現行どおり全地点共通。
[現在計画](CURRENT_PLAN.md)、[乳量計算仕様](MILK_HEAT_MODEL_V0_1.md)、
[乳量実装計画](MILK_MODEL_IMPLEMENTATION_PLAN.md)と併用する。

## 2. 現在ある情報と追加する情報

現行描画は、2Dでは評価点の丸、3Dでは牛床の一部と評価点の円を着色する。
区画の背景色の多くは用途を示す固定色で、計算結果のヒートマップではない。
初期Aは基準案と同じため、既存の「放熱改善」だけでは絶対的な暑熱状態は見えない。

| 情報 | 現在の状態 | 本仕様で行うこと |
|---|---|---|
| 地点ごとの風速、気温、湿度、正味放熱量、成分 | PointResultに60分平均がある | 区画面・選択詳細・エリア集計に使用 |
| 基準案との放熱差 | deltaQrefWにある | 既存の符号を維持し、面へ表示 |
| 放熱不足の60分平均 | 正式な出力にはない | 計算刻みごとに不足を求めて積算 |
| 捕水・蒸発・終了時保持水 | filmに試行量がある | 単位・期間を明記して表示 |
| 平均保持水、機器作用の有無 | 必要な集計値は未整備 | 同じ60分計算中に集計する |
| エリア別統計・未到達地点一覧 | 未整備 | 正式な地点結果から表示用に集計 |
| 日負荷・日乳量 | 新乳量モデルの別出力 | 本仕様の60分マップと混在させない |

PointResult.meanQrefWは地点の正味放熱量であり、乳量モデルの固定Qrefとは別の値。
本仕様では固定値を `referenceCoolingWPerCow`、地点の正味放熱をQと呼ぶ。

## 3. 地点と表示区画の対応

物理計算点は現行の70地点のまま。表示面を広げても計算点の数・重み・水配分を変えない。
表示区画は「この面を代表する地点の値」を示し、面内全域を計算したとは扱わない。

| 対象 | 区画数 | 形状と値の対応 |
|---|---:|---|
| 牛床 | 50 | Layout.stallsの各牛床矩形を塗る。同じIDのstall評価点へ対応 |
| 採食帯 | 12 | feedingゾーンの長辺を12等分し、深さはゾーン内に限定。feed-01〜12へ対応 |
| 待機場所 | 8 | waitingゾーンを長さ方向2列×幅方向4行で分割。既存wait-1〜8へ対応 |

座標はsrc/template/layout.tsと同じ規約（x=長さ、y=幅、heightM=高さ）。
採食帯の区画は物理的な柵を新設するものではなく、表示上の分割。
寸法変更時はLayoutから矩形を再生成し、代表点との対応を維持する。
牛床間の通路、飼料帯、機器室、隔離区画など、評価点のない場所は淡い固定色と「評価対象外」の凡例で示す。
近傍の色を延ばして未計算部分を埋めない。初版では滑らかな補間は行わない。

2D・3Dは同じ区画定義・同じ指標値・同じ色変換を使う。
3Dは床面よりわずかに上へ描画してちらつきを避ける。牛の図形で着色面が見えにくい場合に備え、
「分析表示」を用意する。分析表示では屋根を非表示、牛の図形を輪郭または非表示にし、設備と区画境界を残す。
表示切替で設備設定や数値結果を変更しない。俯瞰表示を常に選択できる。

## 4. 指標・集計期間・色

### 4.1 現在の放熱不足（新しい初期表示）

「現在」は選択中の案を指す。時刻カーソルの瞬間値ではない。
主ラベルは「現在案の放熱不足」、補足は「機器ONから60分平均・仮説指標」とする。

```text
H[i,t] = max(0, referenceCoolingWPerCow - Q[i,t])
meanDeficitW[i] = sum(H[i,t] * dt) / 3600
```

referenceCoolingWPerCowは乳量設定の同名値を参照し、初期値630 W。
この基準は仮定であり、深部体温、実際の蓄熱、健康上の危険度の閾値ではない。
0は「この指標では不足なし」と説明し、「安全」「暑熱ストレスなし」と断定しない。

`max(0, Qref - meanQrefW)`では代用しない。表示用の61サンプルからも再集計しない。
固定の60分平均として、計算刻み（標準1秒、既存検証用0.5秒にも対応）で積算する。
日乳量用のDは24時間・滞在重み付きであり、このマップの平均と同一ではない。

### 4.2 基準案からの改善（既存の定義）

```text
improvementW[i] = mean(Q[選択案,i]) - mean(Q[基準案,i])
```

既存deltaQrefWを使う。正は放熱増、負は放熱減。同じ地点・気象・期間で比較する。
これは「不足量の減少」とは異なる。既に不足0の場所でも放熱が増えれば正になる。
基準案自身は改善0でも、放熱不足マップでは不足のある場所が着色される。

既存の「風速」「気温」は補助の切替として残す。ソーカーの効果で空気温度が必ず下がることは要求しない。

### 4.3 色と凡例

| 指標 | 固定の表示目盛り | 読み方 |
|---|---|---|
| 放熱不足 | 0 / 300 / 600 / 900 / 1200 W以上 | 0は淡色、大きいほど濃い橙色 |
| 放熱改善 | −900 / −450 / 0 / +450 / +900 W | 負は橙、0は中立、正は青緑 |
| 風速・気温 | 現行目盛りを継承 | 単位と範囲を併記 |

目盛りは表示用の設計値であり、科学的な危険度区分ではない。全案・全エリア・2D/3Dで共通。
上限を超えた値は色だけを端色へ制限し、数値は切り捨てない。超過の印と実値を詳細に示す。
無効値・計算待ちは灰色＋斜線、計算対象外は薄い背景＋区画枠なしとし、正常な0と区別する。
色以外にもラベル・選択枠・数値を用意し、色だけで状態を判断させない。

## 5. 選択・詳細表示

区画面のクリック/タップ、地点ドロップダウン、キーボード操作のどれでも同じ選択地点を更新する。
選択枠と詳細見出しに「牛床A-01」「採食03」等を表示。2D/3D・案切替で選択IDを維持する。
設備と面が重なる場合は設備選択・ドラッグを優先し、地点はドロップダウンからも選べるようにする。

主詳細（最大5項目程度）：

1. 放熱不足（現在案/基準案）。
2. 放熱改善（符号と基準案名）。
3. 牛位置の平均風速。
4. 局所気温と湿度。
5. 牛体に届いたソーカー水量（60分）と平均保持水量。

「濡れ方・放熱内訳」を開くと以下を表示する。

- 平均保持水kg、終了時保持水kg、60分の捕水kg・蒸発kg・流出kg。
- 対流、放射、通常蒸発、ソーカー蒸発、結露の平均Wと正味合計。
- 牛の評価高さ（牛床0.5m、採食/待機1.3m）、評価点の位置。
- 局所設備の作用時間割合（次節）、無効な場合の理由。

保持水を実際の皮膚濡れ面積率と呼ばない。捕水と結露を区別し、捕水0でも結露で保持水が生じ得る。
既存captureFractionは複数ノズルの捕水量合計そのものではないため、総捕水kgを主に使う。
ミストが届いたことを牛体への直接散水と扱わない。

屋根裏温度・平均放射温度・反射率・断熱厚さは「全地点共通の屋根条件」へまとめる。
地点を変えてもこれらが同じなのはモデルの境界であり、詳細欄で局所値のように見せない。
主画面の乳量は牛群平均であると表示し、区画選択でその場所の乳量に読み替えない。

## 6. エリア別の平均と残る不足

エリアは牛床A/B/C/D、採食帯、待機場所の6行とし、牛床全体の小計も用意する。
各行から対応区画群を強調できる。行選択はエリア要約、区画選択は地点詳細を表示し、見出しで区別する。

各行の主表示：

- 放熱不足の地点単純平均（W/代表地点）。
- 基準案からの放熱改善の地点単純平均。
- 放熱不足が残る地点数/全地点数。
- 不足が大きい地点（上位3件、同値はID順）。

風速・気温・湿度の平均、最大不足、無効地点数は詳細へ置く。
牛床小計は50地点から直接平均し、13/12/13/12地点の4行平均をさらに単純平均しない。
これらは配置診断の地点平均で、面積平均・牛群滞在加重平均・日乳量の計算値ではない。
全70点単純平均を「牛群平均」と呼ばない。14/6/4の重みは日乳量モデル側だけで使う。

無効地点を黙って除外して全体平均を出さない。1点でも無効ならそのエリアの平均は未評価とし、
有効地点数/全地点数と理由を示す。有効地点の個別値は引き続き閲覧できる。

## 7. 「届いていない」と「不足が残る」の区別

放熱不足が大きいことだけで、設備が届いていないと判定しない。
屋根による放射負荷、湿度、風量不足等で、設備が作用していても不足は残るためである。
初版は科学的な「十分な冷却」閾値を追加せず、以下を別々に表示する。

### 7.1 地点ごとの設備作用診断

60分の各計算刻みで、次を判定し、該当秒数/3600を出力する。

| 設備 | 作用があると数える条件 | 表示語 |
|---|---|---|
| ファン | 稼働ファンによる局所風速の増分が背景風速に対して1e-6 m/sより大きい | ファン送風の作用あり |
| ソーカー | 稼働中ノズルから代表面への捕水流量が1e-12 kg/sより大きい | 牛体への散水到達あり |
| ミスト | 当該セル内でミスト由来の蒸発流量が1e-12 kg/sより大きい | ミスト蒸発の作用あり |

これらの微小値は数値ゼロの判定用であり、有効冷却量や推奨風速の閾値ではない。
ソーカーの残水は供給OFF後も冷却するため、別に平均保持水・蒸発量を表示する。
ミストは供給があっても飽和で蒸発しない場合があるため、「供給なし/供給あり・蒸発なし」を詳細で区別する。
ファン送風が作用しても温風で加熱する場合がある。作用ありを改善・十分と同一視しない。

### 7.2 地図上の強調と一覧

- 「不足が残る地点」：meanDeficitW > 1e-6 W。微小誤差除外であり危険度区分ではない。
- 「局所設備の作用なし」：3設備すべての作用時間割合が0。
- 「不足あり・局所設備の作用なし」：上の両方に該当する地点。輪郭と記号で強調し、件数を表示する。

設備作用なしでも屋根対策や自然の放熱は作用しているため、「冷却効果ゼロ」と表示しない。
停止・向きや位置による未到達・ミストの飽和を、追加の詳細情報で区別する。
この初版診断は60分試行についての判定。日運転の空白時間や24時間の不足を検出したとは表示しない。

## 8. 実装への引継ぎ

次は実装担当がユーザーの実装依頼後に行う作業である。

| 作業 | 主な対象 | 必須の境界 |
|---|---|---|
| 表示区画の共通定義 | template/layout.ts、views共通の補助モジュール | 描画の面と計算のProbeを1対1で結び、物理配置を変更しない |
| 60分不足・平均保持水・作用診断の追加集計 | domain/project.ts、model/simulation.ts、必要ならgeometry.ts | 既存の時間ループで集計、追加の仮想設備シミュレーションを乱発しない |
| エリア集計 | 表示用の純粋関数 | 物理結果を変更せず、無効値・地点数・小計を明示 |
| 面と選択・凡例 | views/svg2d.ts、sceneGeometry.ts、common.ts、viewport3d.ts | 2D/3Dで同じ値・色、設備操作を維持 |
| 指標切替・地点/エリア詳細 | ui/layout.ts、panels.ts、styles.css、main.ts | 60分/日、局所/共通を見出しで区別 |
| 状態・保存・Worker | domain/validation.ts、state/store.ts、worker/protocol.ts | 新指標・結果を正式な型にし、古い結果を最新入力へ混ぜない |

追加する結果フィールド案：meanDeficitW、meanFilmKg、fanActionFraction、soakerArrivalFraction、
mistEvaporationActionFraction、mistSupplyFraction。いずれもPointResultの60分結果に属する。
診断の追加はQや乳量式へフィードバックしない。結果の無効時は新フィールドもnull。
熱プロファイルのうちreferenceの値を表示し、low/highから有利な色を選ばない。

新しい指標はView.metricへ `deficit` を追加する。初期値はdeficit、既存delta/speed/temperatureを維持。
区画IDは既存selectedProbeIdを使う。エリア選択と分析表示は物理入力ハッシュから除外する。
保存形式は実装開始時の版を確認し、既存版との互換ポリシーと新Viewの扱いを先に記録する。
計画だけで版番号を重複採番せず、旧入力を黙って別の意味へ変換しない。

実装順序：指標/区域集計の単体試験 → 共通表示区画 → 2D面と選択 → 3D面と分析表示 →
エリア一覧/詳細 → 保存/Worker/ブラウザの統合確認。
レイ数、評価点数、牛群重み、日乳量モデルを可視化の都合で変えない。
